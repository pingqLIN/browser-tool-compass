# Semantic routing matrix

Read only the relevant route and common gate rules. These are repeatable probe contracts, not executable product commands. An approved adapter must bind each contract to an available read-only operation and satisfy [the adapter contract](adapter-evidence-contract.md). Without that binding, exact probes and runtime availability remain `UNKNOWN`.

| Route | Read-only probe | Pass signal | Forbidden during probe | Failure outcome |
|---|---|---|---|---|
| C1 Public retrieval | Retrieve minimal content from an in-scope public resource without session credentials. | `public_retrieval`: current successful response contains the requested public content. | Authentication, rendered interaction, submitting forms, sending private content. | Failed retrieval is `FAIL`; an auth-only resource makes this route `NOT_APPLICABLE`. Do not escalate to an authenticated profile without scope. |
| C2 Developer inspection | Ask the connected inspection tool for minimal target metadata and advertised inspection capabilities. | `inspection_connection`: live target metadata and the requested inspection capability are available. | Navigation, script evaluation, network-body capture, cookies, instrumentation or configuration changes as availability probes. | Report exact transport/capability failure. C3/C4 may be considered only if they provide the required inspection evidence within all constraints. |
| C3 Session automation | List scoped tabs or targets through the session controller. | `session_connection`: current response confirms a controllable session; `target_ready`: the intended target is identified when the operation needs one. An empty list proves transport only and requires separately authorized target creation. | Creating tabs, navigation, clicks, profile replacement or browser startup as probe shortcuts. | Preserve session/target distinction; a missing required target blocks task readiness. C4 applies only with project ownership. |
| C4 Project-owned tests | Read project identity, ownership, test configuration and dependency metadata. | `project_ownership`: intended root/config/tests are verified; `test_readiness`: declared runtime dependencies are present and the approved test path is identified. | Installing dependencies, initializing scaffolds, running tests, starting servers or writing traces during preflight. | Unknown ownership is `BLOCKED`; no project-owned browser tests is `NOT_APPLICABLE` for this route. Static readiness does not prove test execution or success. |
| C5 Host-integrated visible browser | Inspect current installed integration metadata; use approved read-only runtime connection; query visibility and intended tab handoff. | `installed`: current integration/client identified; `runnable`: active runtime connection to the host browser succeeds; `visible`: intended controlled tab is shown on the requested user-facing surface. | Creating/opening/showing tabs, foreground activation, restarts, cache edits or trust changes to force a probe pass. | Record all three gates separately. Hidden or missing handoff fails `visible`; blocked runtime does not negate installation evidence. No alternate surface satisfies an explicit C5 requirement. |
| C6 User-profile integration | Query an existing integration runtime and sanitized active profile/tab identity metadata. | `integration_runtime`: live integration handshake; `profile_binding`: authoritative metadata ties it to the authorized profile/session and required target. | Reading cookie values, enabling extensions, installing native hosts, copying profiles, or substituting an empty profile. | Working integration without binding is `UNKNOWN` binding and blocks use. C7 is eligible only when the user did not require the integration surface and the same profile constraints hold. |
| C7 Existing authenticated connection | Verify an already-existing connection, then compare sanitized authoritative profile/session identity and intended target metadata against the authorized binding. | `endpoint_connection`: current browser protocol handshake; `profile_binding`: verified intended existing profile/session and required target, with non-sensitive authenticated-state evidence when authentication is required. | Starting a debug browser, changing endpoint hostnames or profile, logging in, inspecting credentials or accepting consent as probes. | Endpoint discovery alone is `UNKNOWN` connection. Handshake alone does not prove profile/authentication; missing binding blocks use. Do not switch to a fresh browser on a login screen. |
| C8 Remote browser service | Within explicit remote scope, use a documented non-mutating capability/status query and approved profile identity metadata if needed. | `remote_scope`: authority covers service, data and target; `remote_readiness`: existing service responds and any required approved remote profile is bound. | Uploading local files/session data, creating profiles or sessions, provisioning resources or incurring unapproved charges as availability checks. | Missing remote authority is `BLOCKED`. If only mutating probes exist, readiness remains `UNKNOWN` until a separate authorized operation; acceptance/queue receipt is not execution. |
| C9 Local CLI smoke | Inspect approved executable provenance and a documented no-side-effect availability operation. Verify the target is already available through an authorized read-only check. | `cli_available`: current installed CLI is callable; `target_ready`: intended target is reachable. | Package-run auto-install, server/browser startup, configuration writes or creating a smoke session as availability checks. | Missing CLI blocks C9; choose a constraint-compatible route only. Help/version output proves CLI availability, not browser control or application behavior. |
| C10 Desktop interaction | Query approved desktop runtime status and non-sensitive surface metadata; inspect a screenshot only if its capture and visible contents are within scope. | `desktop_runtime`: live interaction surface exists; `desktop_scope`: requested desktop target and capture/input scope are authorized. | Clicking, keystrokes, broad desktop capture, elevating privileges, bypassing browser/auth checkpoints. | Missing runtime is `BLOCKED`; unknown surface identity is `UNKNOWN`. Desktop control cannot satisfy a required browser API evidence contract. |
| C11 Extension scaffolding | Read target ownership/existence and available approved scaffolding guidance. | `scaffold_scope`: explicit creation/governance request and owned target; `scaffold_readiness`: instructions/resources available without overwriting existing work. | Creating files, invoking generators, downloading packages or overwriting non-empty targets during probe. | No creation/governance request is `NOT_APPLICABLE`; uncertain ownership is `BLOCKED`. Preflight pass authorizes no file write by itself and is not extension runtime evidence. |

## Common gate rules

`PASS` means the named proposition has direct current evidence. `FAIL` means an executed valid probe returned evidence contradicting it. `BLOCKED` means authority, trust, safety or a known missing dependency prevents proceeding. `UNKNOWN` means absent, stale, ambiguous or unrun evidence. `NOT_APPLICABLE` means the gate/route does not pertain to this task, not that a failed required gate may be waived.

An inaccessible authoritative identity source leaves binding `UNKNOWN`; do not infer it from an endpoint, window title or familiar URL alone. A privacy-sensitive status check that cannot be safely sanitized is blocked, not a reason to inspect session secrets. Empty metadata responses cannot prove a target exists.

All probes exclude operations that create sessions or billed resources. If the environment's only probe has such effects, classify it honestly and require a separately authorized workflow. Record the observed gate, not a blanket route pass. A task can proceed only when every applicable required gate and hard constraint is satisfied.
